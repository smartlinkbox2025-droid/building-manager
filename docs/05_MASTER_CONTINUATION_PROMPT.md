# البرومت الرئيسي لإكمال Building Manager Enterprise

تصرّف كمهندس برمجيات أول متخصص في React وTypeScript وIndexedDB وPWA والتطبيقات المالية العربية RTL.

## المدخلات الإلزامية

1. مشروع ZIP الحالي العامل على GitHub Pages.
2. وثيقة المواصفات الأصلية `برومت التطبيق.md`.
3. الملفات داخل مجلد `docs/`، خصوصاً:
   - `00_PROJECT_BASELINE.md`
   - `01_GAP_ANALYSIS.md`
   - `02_IMPLEMENTATION_ROADMAP.md`
   - `03_MASTER_CHECKLIST.md`
   - `04_ACCEPTANCE_TESTS.md`

## قواعد صارمة

- لا تعِد بناء المشروع من الصفر.
- لا تحذف أي وظيفة تعمل.
- لا تغير اسم IndexedDB الحالي `BuildingManagerDB`.
- لا تعدل مخطط الإصدار 1؛ أضف Dexie migrations بإصدارات جديدة.
- حافظ على بيانات المستخدم القديمة.
- حافظ على `HashRouter` ومسار GitHub Pages `/building-manager/` ما لم يوجد سبب موثق.
- لا تستخدم Backend أو Firebase أو Supabase.
- العملة الافتراضية SAR والواجهة عربية RTL.
- لا تستخدم LocalStorage للبيانات المالية أو المرفقات.
- لا تنشئ أزراراً وهمية.
- لا تعتبر المرحلة مكتملة قبل نجاح `npm install` و`npm run build`.
- بعد كل مرحلة حدّث `03_MASTER_CHECKLIST.md` ودوّن التغييرات في `CHANGELOG.md`.

## منهج التنفيذ

نفّذ مرحلة واحدة فقط في كل دورة بحسب `02_IMPLEMENTATION_ROADMAP.md`.

قبل التعديل:
1. اقرأ الملفات المرتبطة.
2. حدد أثر التعديل على قاعدة البيانات.
3. اكتب Migration آمن عند الحاجة.

بعد التعديل:
1. شغّل TypeScript build.
2. شغّل Vite build.
3. افحص الأخطاء.
4. لا تنتقل للمرحلة التالية قبل نجاح الحالية.
5. سلّم ZIP كامل وليس مقتطفات.

## المهمة الحالية

ابدأ بالمرحلة 0 ثم المرحلة 1 فقط:

- تثبيت إصدارات الحزم وإنشاء lockfile.
- تحسين بنية الأخطاء دون تغيير الواجهة جذرياً.
- إضافة مخطط Dexie جديد بالجداول الناقصة.
- كتابة migrations تحفظ بيانات الإصدار 1.
- تحديث الأنواع TypeScript.
- إنشاء خدمات أساسية للمرفقات وتسلسل الإيصالات.
- عدم بناء الصفحات المتقدمة قبل اكتمال الأساس.

## مخرجات الدورة

- ZIP كامل قابل للرفع على GitHub.
- تقرير ملفات تم تعديلها.
- نتيجة البناء.
- العناصر التي تم إغلاقها من Checklist.
- المخاطر أو العناصر المؤجلة بوضوح.
